How to use this page

This is the short list, not the whole library. It exists because the site has grown past the point where a first-time visitor should have to guess which of forty pages to open first. The page is organised by what you are trying to do — learn a task, look something up, or play — rather than by what the thing is called.

The Learn column is ordered by dependency, not by popularity. If the vocabulary is unfamiliar, read the lattice overview first: it defines the six words that everything else assumes. Then the task-brief guide, because a brief is the input to every other workflow here. Then the handoff playbook, then the claims guide. You can read them out of order, but the worked examples in the later guides quietly assume the earlier terms, and the earlier guides are the ones that make the later ones short.

The Reference column is for looking things up rather than reading through. The champion directory is the roster; the individual profiles say when a role helps and when it is the wrong tool. The DeepSeek Peak Alarm is a timer for people who pay per token. The editorial standards page is the site's own rulebook, and it is worth reading if you are deciding whether to trust a page here — it says what gets published, what gets refused, and how a correction is handled.

The Games column is the arcade. Eighteen titles, no account, no install, and a shared ledger of results. They are on this site because building them is how a number of the technical lessons were learned: a game fails visibly, in ten seconds, in a way a document does not.

What this page deliberately does not do

It does not rank tools by commission, and there are no affiliate links on it. It does not publish a “top ten AI tools” list, because those lists are almost always written from press releases rather than from use. It does not link to something because the owner asked. A link is here because the page behind it teaches something, documents a tool this site actually runs, or is a public record worth reading — and every one of those links is checked when the page is next reviewed.

If a link dies, that is a bug, not a judgement about the destination. Report it with the contact page and it gets fixed on the next pass, which is also when the review date at the top of this page moves.
